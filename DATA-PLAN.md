# Data Plan

## Context provenance
- `The application must contain exactly 125 core lessons in the correct numerical order.` (verbatim build request §1/§3; drives the 125-lesson manifest with stable numbers 1–125)
- Full 125-topic English manifest supplied verbatim in §3 of the request (Lessons 1–125, from 'Meeting New People' to 'Things I Need and Do Not Need'); used as the authoritative curriculum — no topics invented or substituted.
- `Do not simply replicate another company's proprietary design, audio recordings, or copyrighted lesson content.` (request §1) — all vocabulary, Bengali translations, definitions, examples, micro-stories and lesson stories are authored originally for this build; the LingoHut URL is used only as a structural reference for topic order, never scraped or copied.
- Learner context from MEMORY.md: Sifat, Bengali-speaking, IELTS target 7.5 from ~4.5 — beginner-friendly Bengali-first explanations throughout.

## Tested sources
### Supplied curriculum manifest (in-request)
**Used by**: getCurriculum / lesson data files
**Test command**: read of the verbatim build request §3 — 125 numbered topics present, no gaps (1–25, 26–50, 51–75, 76–100, 101–125)
**Sample output**: 1 Meeting New People … 61 Fruits … 100 Emergency Expressions … 125 Things I Need and Do Not Need
**Processing**: each topic gets a hand-authored Bengali title, category, icon key, objectives, topic-specific vocabulary entries (words/phrases/sentences with Bengali meaning, part of speech, IPA where standard, English definition, Bengali explanation, example + Bengali translation, sense-matched synonyms/antonyms with their own Bengali meanings — or an explicit 'no natural antonym' note), a per-entry micro-story/dialogue (EN+BN sentence-aligned), and one bilingual lesson story with comprehension questions. Quizzes and all 10 games are derived programmatically from the lesson's own entries at runtime, so no lesson shares another lesson's vocabulary.

## Long-term data behavior
- **Refresh policy**: curriculum content is static authored data shipped with the app; no external refresh. User data (progress, word states, notes, attempts, settings) persists in the artifact DB and is read live on every open.
- **Growth**: user rows grow with study activity — lesson progress (≤125), word review states, review history, practice attempts, study sessions, bookmarks/notes, custom words.
- **Ordering**: lessons strictly by number 1–125; review queue by next-review date ascending; dictionary results exact-match first then partial.
- **Time semantics**: review due dates and study sessions stored as instants, rendered viewer-local; streak computed from local calendar days with activity.

## Rejected approaches
- **Tried**: scraping/copying LingoHut lesson content
  **Why rejected**: explicitly forbidden by the request and copyright rules; all content authored originally instead.
- **Tried**: claiming full editorial verification for all ~1,200 entries
  **Why rejected**: content ships with an honest completeness/coverage view (per-lesson entry counts, story status) rather than a false 'verified' label; admin view exposes the manifest for future correction.
- Imagery not needed: the app is a text/audio learning tool; topic icons are Lucide-style inline glyphs and progress is charted from real stored attempts — no photographic subjects are depicted.

## Update — checkpoint exams, IELTS speaking final, lesson feedback & Bengali motivation (2026-11-21 edit)
- The learner asked for: an exam after every 5 lessons on those 5 lessons; a final exam after the last lesson in the style of a full IELTS speaking test with voice input and an improvement mark; a feedback system after completing each lesson (a "dopamine hit"); and Bengali motivation text in the head/body of the app.
- New module `client/src/exams.tsx`: (1) **25 checkpoint exams** (blocks 1–5 … 121–125) in a new Exams view (sidebar + mobile nav + Home section + Stats rows). Each exam unlocks when all 5 lessons in its block are completed and builds ~17 questions only from those 5 lessons' own entries — meanings both directions, a listening question, fill-the-blank from their examples, synonym/antonym questions only where true relations exist, and story-comprehension questions from their stories. Pass mark 60%; scores persist via the existing `recordAttempt` action with kind `checkpoint-<last lesson>` (no schema change), best score/pass state derive from stored attempts. (2) **Final exam**: unlocked when Lesson 125 is completed; IELTS structure — Part 1 interview (4 questions), Part 2 cue card (describe a place, with the standard "you should say" bullets), Part 3 discussion (3 questions). Answers come from the browser Web Speech API recognition (same pattern as the existing Speaking tab; the recognized text lands in an editable box) or typing where recognition is unsupported. Scoring is a transparent, transcript-only practice estimate — fluency (words spoken / speaking speed when the mic was used / linking words), lexical resource (distinct words used), grammatical range (sentence count, average sentence length, connectors), task completion — each shown with the measured numbers behind it, and labelled in Bengali and English as NOT an official IELTS score (pronunciation cannot be heard). Attempts persist as kind `final-speaking` (total 90, correct = band × 10); the intro and result screens list attempt history and the band change since the first/previous attempt, which is the speaking-improvement tracking. Scores under 10 spoken/written words are shown but not saved. (3) **Celebration**: after every finished lesson assessment a feedback overlay opens — confetti + Pip + Bengali praise + real stats (lessons completed, streak, mastered words) + a motivation line on completion (70%+, the app's existing completion rule), and a warm Bengali encouragement card with review/retry actions below 70%, so every assessment ends with a feedback moment. Passing a block-final lesson (5, 10, …) offers the checkpoint exam; passing Lesson 125 offers the final exam. (4) **Motivation**: 12 original Bengali motivation lines (`MOTIVATIONS`) rotate daily — Home banner with a shuffle button, a sidebar card, a per-lesson line under every lesson header, the exams page, and inside the celebration overlay.
- Verified live in the audit sandbox (probe): Exams hub with block 1–5 Ready and the final unlocked after seeding lessons 1–5 + 125 complete; the full 17-question checkpoint exam for lessons 1–5 answered through to its result + answer-review screen; the final exam driven through all 8 questions with typed answers to a result screen (practice band 8.5, four criteria with measured stats, "+3.5 band" improvement vs a previously recorded 5.0 attempt); Lesson 6's assessment driven to the below-70% encouragement overlay. Not verifiable in the sandbox: actual microphone capture/speech recognition (no mic in the audit browser) — the voice path is the same Web Speech code as the existing, previously shipped Speaking tab, and typing always works as the fallback. Sandbox fixture rows (seeded completions/attempts) never ship to the learner's data.
